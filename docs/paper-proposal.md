## 一、题目（暂定）

**Shadow Mechanisms: Trigger-Conditioned Counterfactual Accounting of Agent Harness Components under Model Churn**

中文：影子机制——模型更迭下 agent harness 机制的触发条件反事实核算

**一句话主张：** harness 的大部分机制是"反应式"的：只在特定事件发生时介入。利用这一结构，可以把一次昂贵的整轨迹消融，换成"在影子记录的触发点处分叉"的局部估计。这样更便宜、方差更小，而且可以在生产流量上持续运行。据此可以在模型升级时，不做全量消融就判断哪些机制已经过期。

| 低成本 A/B | DeltaSelect (2609.19607)、How Many Tasks Are Enough (2607.12338)、Bayesian Optimal Stopping (2608.14425) | 通过挑选任务、提前停止来降低成本 | 在**任务维度**上省钱；和我们在**轨迹内部**省钱正交，可以叠加 |
| harness 随时间变化 | Don't Blame the LLM (2607.03691) | 固定模型，改变 harness 版本（35 个版本） | 反方向：**固定机制，改变模型版本**，追踪每个机制的效应衰减 |
| 虚假完成 | Confident Closing (2606.09863)、Overclaiming Propensity (2609.20812) | 刻画虚假成功的比例（τ² 失败中占 44–52%） | 可以作为我们的一类机制（声明门、校验门）的动机，不是本文主线 |

**缝隙（我们的三点贡献）：**

1. **分析单位：带触发点的机制。** 已有工作的单位是"整个 harness""组件（planning / memory 等抽象模块）""步骤"或"agent"。我们的单位是工程师真实会写、会删的那段代码，并且显式区分反应式和常驻式。
2. **估计器：触发条件分叉，加上影子模式。** 把 Replay Gap 和 CAR 的分叉思路迁移到机制层面，并利用"未触发的轨迹效应为零"的结构，得到更便宜的估计。影子模式让同一套估计的第一项 P(触发) 可以在生产上零成本获得。已检索到的工作里没有看到这个组合。
3. **经验发现：模型更迭下的机制衰减面板。** 固定一组机制，在多个模型家族的连续版本上测量效应，并检验"影子触发率的下降是否能预测效应的消失"。*Don't Blame the LLM* 做的是反方向；*More Is Not Always Better* 只比较了同一代的两个规模（8B / 70B）。

**新颖性自评：中等偏上，但窗口很短。** 单独看每一个要素都有前人工作；新颖性来自三者的组合，以及"机制 + 触发点"这个单位的选择。这个方向每周都有新论文，预计 2–3 个月内可能出现相近工作，所以**速度比完美更重要**：建议先挂 arXiv 占位，再投会议。

## 三、研究问题

- **RQ1 有效性。** 以大样本全量留一消融为"金标准"，触发条件分叉估计给出的机制效应，在符号、排序和保留/删除决策上与之一致的比例是多少？在哪些机制类型上会失效？
- **RQ2 效率。** 达到相同置信区间宽度或相同决策一致率时，触发条件分叉相比全量 LOO、相比 DeltaSelect 式的任务子集，要花多少 token 和美元？两者叠加又如何？
- **RQ3 衰减。** 在同一家族的连续模型版本上，各类机制的效应如何变化？哪类机制最先被吸收？影子触发率的变化能否在不做消融的情况下预测效应的消失？
- **RQ4（可选）交互。** 触发点重叠的机制对之间，交互效应有多大？只在重叠对上做小规模析因，能否以低成本抓住大部分交互？

## 四、方法

**4.1 机制形式化。**

机制 m 是一个作用在 harness 状态上的变换，带触发谓词 τ_m(s)。
- 反应式：只有当 τ_m(s)=1 时，m 才改变状态；
- 常驻式：τ_m ≡ 1，从第 0 步起生效。

**4.2 影子执行。**

以 m 关闭的配置运行，在每一步计算 τ_m(s)。若为真，记录 Activation，包括环境快照句柄和消息历史，但不执行干预。

**4.3 触发条件分叉估计。**

在第一个 Activation 处分叉出三支：
- ON：执行 m；
- OFF：不执行 m；
- CTRL：与 OFF 同配置的对照分叉。

之后各自走完全程。估计量：

```
Δ̂_m = P̂(触发) × mean_i [ Y_ON,i − Y_OFF,i ]
```

用 CTRL 与 OFF 的差异估计"分叉本身的噪声"下界，作为显著性的地板；方差由 bootstrap 给出。

需要处理的问题：
- **多次触发。** 默认只在第一次触发处分叉，并记录后续触发次数；对多次触发型机制（例如循环打断）另做敏感性分析。
- **常驻式机制。** 退化为从第 0 步开始的配对 A/B。
- **耦合陷阱。** 按 2609.06445 的结论，公共随机数耦合下的零效应不能说明机制无作用。因此报告边际效应，不只依赖 CRN；对照分叉用于噪声地板，而不是作为因果证据。
- **环境与模拟器的随机性。** 分叉点需要重建工具环境和用户模拟器的状态。Replay Gap 发现 FP8 推理下温度 0 也不确定，所以要记录服务精度，并把它作为协变量。

**4.4 衰减面板。**

固定机制库，在每个模型版本上同时做两件事：
- 用影子模式测 P(触发)；
- 用分叉测 E[Δ | 触发]。

然后检验：前后两个版本之间 P(触发) 的变化，与完整 Δ 的变化是否相关。

## 五、实验设计

**机制库（约 12–16 个）。** 从现有概念稿里的 16 个机制出发，按 stage 和 kind 分类。示例：

| 机制 | stage | kind |
|---|---|---|
| Schema Fix Adapter | tool_call | reactive |
| Loop Breaker | tool_call | reactive |
| Context Slimming | agent | reactive（按阈值触发） |
| Pre-flight Policy | policy | persistent |
| Dynamic Tool Scope | policy | persistent |
| Structured Checklist | agent | persistent |
| 声明门（claim gate，新增，对应虚假完成问题） | claim | reactive |

**任务集。**
1. τ²/τ³ airline、retail：有前期调试经验，而且带用户模拟器，能检验模拟器分叉的难点；
2. Terminal-Bench 2.x 子集：编码类，环境可容器化快照，方便与已有文献对照；
3. （可选）自建 30–50 个中文 To B 文档审核任务：可以成为独特的数据贡献，但会增加工作量。

**模型面板。**
- 至少两个国产家族各取 2–3 个连续版本（例如 GLM 与 DeepSeek 的近几代），外加 1 个海外前沿模型作为对照。
- 具体版本以实验开始时可获得、并且能控制服务精度的为准。
- 国产模型多版本的面板是相对少见的数据，也符合目标用户的实际情况。

**金标准与预算。**
- 在一部分"机制 × 模型"组合上做大样本全量 LOO（例如每任务 k=8 或以上），作为 RQ1 的参照；
- 其余组合只跑分叉估计；
- 所有比较都附上同预算的重试 / best-of-n 基线，回应 Rethinking 一文的批评。

**报告口径。** pass@1、pass^k、置信区间、token 与美元成本、分任务退化，全部报告，不只报平均通过率。

## 六、主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 分叉估计与全量 LOO 不一致 | RQ1 为负 | 负结果同样可以发表，并且要刻画失效的条件（例如长程依赖、多次触发）；产品侧退回到"影子触发率 + 挑选任务"的方案 |
| 环境无法精确重建到分叉点 | 估计有偏 | 优先使用可快照的环境（容器、确定性工具 mock）；对用户模拟器固定随机种子并记录其输出；用对照分叉量化残余噪声 |
| 近期出现高度相似的工作 | 新颖性下降 | 先发 arXiv；把"国产模型多版本面板"和"生产影子信号"作为难以复制的部分 |
| 算力成本 | 实验范围受限 | 用 RQ2 的方法本身节省算力；面板先只覆盖两个家族 |
| 原来的 +10pp 在严格协议下不复现 | 叙事受影响 | 如实报告；"严格协议下缩水"本身就是支持本文动机的证据 |

1. **经验型论文："国产模型换代下的 harness 机制半衰期"。** 只做 RQ3，不提新的估计器。新颖性低一些，但数据独特，工作量最小。
